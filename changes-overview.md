# Changes: multi-asset support

Written for a ziplime maintainer who has to review, merge and support this.

Before this, ziplime traded equities. The futures tables existed but nothing wrote to them and the
continuous-future layer was dead code; there was no notion of a bond at all.

It now trades **equities, bonds and futures, together, in one portfolio**, because the engine
dispatches on instrument type wherever the three disagree. Section 3 is the part worth reading
closely.

**Test suite: 265 tests — 261 passed, 4 xfailed.** The four xfails pre-date this work. `tests/` had
no tests before it. By area: 99 futures, 101 bonds, 27 correctness regressions, 17 cross-asset,
12 connector registry, 9 dividends.

> **Vendor connectors are a separate pull request.** This change ships the registry that makes
> connectors pluggable, and Yahoo Finance. Everything specific to one vendor — its client, its
> instrument tables, its examples and the findings about its API — lives with that connector.

---

## 1. Read this first: results that moved

Existing backtests will not reproduce their old numbers. Each of these is a fix, not a regression,
but a maintainer comparing against a stored result needs to know which.

| Change | Effect on results |
| --- | --- |
| Variation margin was applied in one direction only | **Large.** A long futures position could not lose money. One example went +10.02% → −4.16% |
| Deliverable contracts force-close before the notice date | Strategies trading a deliverable root roll earlier; two examples moved by more than five percentage points |
| `auto_close_date` now sits strictly after the last tradable session | −2.97% → −3.42% on the example that exercised it |
| Default roll moved one session before auto close | Rolls now book commission and slippage. Rolling *on* auto close let `_cleanup_expired_assets` close the leg for free |
| Commission now reaches the cost basis | Reported cost basis and realised P&L move **for equities too**. Cash was always right |
| Expired positions are now liquidated | Exposure, leverage and position counts change; **P&L does not** — a cash-settled contract closes at its last mark |
| `perf["positions"]` holds snapshots, not live objects | The recorded past stops mutating as the run proceeds |
| Bundle load window includes the first session east of UTC | Such backtests gain one session at the start |

The last four are pre-existing bugs that affect equity-only runs. They are fixed in the companion
pull request, `fix/correctness-regressions`, which should be reviewed and merged first.

## 3. The asset-class model

**Three instrument types settle by rules that contradict each other, and they share one cash
balance, one ledger and one set of performance figures.**

| | cash paid on opening | position value | exposure | pays out via |
| --- | --- | --- | --- | --- |
| **Equity** | `price × amount` | `price × amount` | same as value | dividends |
| **Bond** | `dirty price × amount` | dirty value | same as value | coupons, amortization, redemption |
| **Futures** | **nothing** — margin only | **zero** | `price × multiplier × qty` | daily variation margin |

Getting one wrong is not a rounding error. A bond quote is a percentage of face value, so reading
it as money understates the position by a factor of ten on a standard 1000-unit nominal. A future
costs nothing to open, so sizing it by "cash available" is unbounded.

### 3.1 Where the dispatch lives

An instrument is reached as `position.asset.asset` — `Position.asset` and `Transaction.asset` are
the **listing** (`ExchangeAsset`), and `.asset` is the instrument. Getting this wrong meant every
futures branch tested the listing and was therefore always false.

| Concern | Where |
| --- | --- |
| Cash on a fill | `Ledger.process_transaction` — three branches |
| Position value and exposure | `finance_ext.calculate_position_tracker_stats` |
| Order sizing by money | `TradingAlgorithm._calculate_order_value_amount` |
| Commission and slippage model selection | `SimulationExchange._model_for`, keyed by `type(asset.asset)` |
| Commission into the cost basis | `PositionTracker.adjust_commission_cost_basis` |
| Scheduled payouts | `Ledger.process_dividends`, `process_bond_events`, `redeem_matured_bonds` |

Adding a fourth class means touching that list. `SimulationExchange._model_for` now raises a named
error rather than a bare `KeyError`, so the first thing a new class hits tells you what is missing.

### 3.2 Bonds

`ziplime/finance/bonds.py` holds the arithmetic and `BondBook`, which caches coupon and
amortization schedules. It exists because **the ledger settles a transaction inside a synchronous
call** and cannot reach the database there — schedules are loaded when a bond is first ordered and
once per session for every bond held.

Three corrections stand between a bond quote and the ledger:

1. **Quotation.** The quote is a percentage of face value, not money.
2. **Accrued interest.** The tape carries the *clean* price; settlement is at the *dirty* one. On
   an 8% coupon this averages about 4% of face value per trade.
3. **Amortization.** An amortizing issue repays principal in instalments, so the nominal a quote is
   a percentage *of* shrinks, and so does the coupon computed on it.

Accrual comes from the schedule when one is stored — elapsed days over the length of the coupon
period, which needs no day-count convention. `DayCount` (ACT/365, ACT/360, ACT/ACT, 30/360) is the
fallback for a bond whose schedule was never ingested.

Redemption is booked explicitly, not left to auto-close: a matured bond does not trade, and closing
the position at the last printed bar books a gain or loss that never happened.

### 3.3 Futures

Chains (`futures_root_symbols`), `OrderedContracts`, `RollFinder` / `CalendarRollFinder` /
`VolumeRollFinder`, and continuous-future resolution inside `DataBundle.get_data_by_limit` — rolls
become segments, each read from the contract actually held, back-adjusted onto the newest level.

Plus margin (`ziplime/finance/margin.py`), where the key fact is that **margin currency is not
quote currency**: an exchange may collect its local currency for a contract it quotes in dollars.
Requirements are reported per currency; asking for one number across two raises.

Settlement type (`CASH` / `PHYSICAL`) drives the lifecycle dates: a deliverable contract is
force-closed *before* its notice date, while still tradable, so a backtest never carries a position
into a delivery window.

### 3.4 One bundle, not three

A simulation reads from a **single** market data source, so every instrument a strategy touches has
to be in one bundle. `ingest_market_data` therefore accepts several asset types — and, better, the
resolved listings, which removes symbol resolution from the path entirely.

That matters more than it sounds: **a ticker is unique only within an asset class.** A database
carrying more than one will contain tickers that exist under two — an equity vendor listing a
futures ticker as an equity is the usual way it happens. Resolving by name alone tags the bars with
the other instrument's sid, and the strategy then silently trades nothing.

## 7. Known gaps

Ordered by how likely they are to matter.

* **Cash has no currency.** Margin requirements are reported per currency, but the portfolio adds
  P&L across currencies as one number.
* **Margin is modelled, not enforced.** No margin calls, no buying-power constraint.
* **Delivery is avoided, not simulated.** A deliverable position is force-closed before its notice
  date; assignment and squeeze risk are not modelled.
* **Settlement type is not machine-verified.** No vendor API observed exposes the field, so the
  CASH/PHYSICAL classification is supplied per root by the connector and is domain knowledge. It
  moves results — see §1.
* **No credit risk on bonds.** An issuer always pays.
* **Offers are not exercised.** A put or call window is recorded and left there.
* **`data.current` is not positional.** It takes a *set* of assets and omits any with no bar today,
  so reading its rows by position can pair a price with the wrong instrument. Every example keys on
  `sid`; nothing in the API enforces it.
* **Root symbols are keyed without a venue.** `futures_root_symbols` keys a chain by root symbol
  alone, so two venues using the same code collide. A composite `(root_symbol, mic)` key is the
  modelling-correct fix and needs a wider migration.
* **`yfinance` is a mandatory dependency** although only the Yahoo connector uses it. Making it an
  extra changes what `poetry install` produces, so it was left as a maintainer decision.
* **Price limits, locked markets and stale-price `can_trade()`** are disclosed, not modelled.

`context.realism_warnings()` reports the runtime-relevant subset of this list during a simulation.
